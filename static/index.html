    参数说明
    • 单次阅读多少字：每一小截文档最长大约多少汉字/英文字母一起送给模型。数字越大，单次看得越多，上下文更完整，但一次请求更「吃力气」，失败或超时时代价也更大；越小，切得越碎，调用次数变多、总时间可能变长。
    • 相邻两段重复一点：上一段的末尾和下一段的开头会故意重复一小段，避免刚好从一句话中间切开，导致前后接不上、漏信息。
    • Markdown 按标题切：仅对文件名以 .md / .markdown 结尾的上传生效。按行首 # 形式的标题（1～6 级）在您选定的那一级新开一段；标题前若有前言会单独成段。若全文没有该级标题，或某一节仍太长，会自动再用「单次阅读多少字」切细。PDF、Word、纯文本等仍按字数切。
    • 同一段多问几遍：同一个小片段可以让模型再答一轮、再答一轮，多挖几批题。总次数大致是：文档小段数 × 这里填的遍数 × 模型个数（模型多也会成倍增加）。
    • 每小段出几道题：不在下面填，请到出题说明 → 数量策略里用平常说话写清楚（例如固定多少对，或交给模型看内容决定）。
    • 回答有多「敢发挥」：可以理解成创意程度。数字低，模型更老实、更贴着原文写，适合入库检索；数字高，更容易联想、发挥，偶尔可能多写原文没有的东西。
    • 网络不稳时多试几次：某一截出题失败时，程序会自动隔几秒再试；试完仍失败会跳过这一截，前面已经成功的不会丢。若密钥写错，一般会整单停掉，避免白花钱。
    • 单次回答最长允许多长（兼容网关）：限制模型这一次最多能写多长。要出的题目很多、答案很长时，需要留足空间，否则回复可能被截断半截，表格会缺题。走公司兼容接口时才需要关心这一项。
    • API 调用模式：默认单线程，按顺序一段一段调用，最稳定。开启多线程后可同时发起多个请求，整体更快；并发数无硬性上限，若设得过大可能在本地运行日志里出现限流、超时等报错，建议从默认并发 5 开始逐步调整。
